# Загрузка записей Devnet — текущая реализация

Активная страница: https://coolbears-nfts.com/solana-load/ . Старая `/solana-upload/` — только HTML-переход на неё. Её контроллер, SDK, группа из 250 записей, ручной отправитель, RPC-pacing и прежние тесты удалены. Новые файлы: `solana/load-{client,model,rpc}.mjs`, `solana-load/`.

## Использование

В браузере Phantom выбрать Solana Devnet, открыть страницу и подключить кошелёк владельца. Прогресс читается автоматически. Нажать «Загрузить следующие 25» один раз и подтвердить в Phantom. Сам кошелёк подписывает и отправляет одну транзакцию; сайт выполняет максимум три чтения для подтверждения результата. Следующий пакет запускается только новым нажатием владельца. При задержке подтверждения отдельная кнопка проверяет только состояние.

Сохранённый ранее HTTPS RPC проекта автоматически читается из прежней настройки того же браузера; переноса API-ключа в чат не требуется. Он используется для подготовки и проверки Devnet. Отправка происходит через RPC самого Phantom в выбранной в кошельке сети. Обе точки нельзя называть одним подключением. Публичные RPC по-прежнему могут ограничивать запросы; приложение не может отменять их лимиты или гарантировать скорость окна Phantom.

## Сохранение и восстановление

`coolbears-operator:devnet-load-v2` — новая история. Обе старые блокировки вкладок сохраняют взаимное исключение с уже открытой старой страницей. Предыдущая история копируется целиком в legacyArchive до пометки её ключа как retired/version2. Старая вкладка после этого не пройдёт собственную проверку version1. Архив не является исполняемым загрузчиком. Незавершённые прежние группы только проверяются: присутствие записей, finalized-ошибка либо null signature status после доказанного срока. Очередь не переподписывается. Страница и сборка не импортируют старый код.

Для новой попытки сохраняется намерение ДО signAndSendTransaction, включая диапазон и исходный срок. Затем сохраняется возвращённая подпись. Отказ сохранения останавливает вызов кошелька. Обновление прогресса не заменяет текст результата предыдущей попытки. Диагностика RPC и время ожидания ответа Phantom сохраняются в истории; в экспорте нет URL/ключа RPC, приватных ключей или сырых ответов провайдера. Пауза кошелька включает действия пользователя, не означает измерение времени открытия диалога.

Phantom может обновить blockhash перед отправкой. Поэтому истечение исходного срока НЕ доказывает неуспех новой wallet-managed транзакции. При потерянном ответе новая отправка блокируется до подтверждения записей или finalized-ошибки известной транзакции. Null-status/закрытие страницы/общая ошибка не очищают pending. Отмена с кодом4001 и документированные отказы до отправки (4100,-32000,-32002,-32003,-32601) разрешают новую ручную попытку; их сообщение сохраняется. Автоматической переподписи, повторной отправки и автоматического следующего пакета нет. При неизвестной отправке потребуется разбор сохранённого результата; обхода этой проверки через очистку браузера не предлагать.
