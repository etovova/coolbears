# Devnet v6 — явная отправка через выбранный RPC

Версия: `devnet-20260922-6`. Этот файл описывает код и границы проверки; статус публикации определяется GitHub Actions и контрольной записью проекта.

## Причина изменения

Реальный отчёт v5 от 22 сентября 2026, 09:20 UTC: подготовка через Helius заняла 679 мс, оставалось 147 блоков; Phantom Wallet Standard ответил внутренней ошибкой −32603 через 20 секунд. Подпись отправленной транзакции не получена, операция впоследствии отмечена expired. Свежая подготовка подтверждена. Код −32603 не устанавливает причину сбоя внутри кошелька.

## Изменение

После применения своего Devnet RPC появляется отдельная кнопка «Phantom: отправлять через свой RPC», если injected Phantom поддерживает signTransaction. Пользователь явно выбирает этот способ. Обычные кнопки подключения сохраняют прежний signAndSendTransaction через кошелёк; автоматического переключения после ошибки нет.

Сайт проверяет условия, Devnet и симуляцию, сохраняет операцию, затем просит подпись. Возвращённое сообщение должно точно совпасть с подготовленным: версия v0, плательщик, NFT, blockhash, порядок подписантов, обе криптографические подписи и исходная подпись NFT проверяются. Проверенная подпись транзакции сохраняется до единственной отправки через выбранный RPC с preflight. Новая подпись, замена blockhash или автоматическая повторная отправка не выполняются.

Поздняя подпись после таймаута сохраняется как свидетельство без отправки. Смена аккаунта, выбранного адреса RPC, уход со страницы, конфликт или ошибка журнала останавливают отправку. Результат POST не приравнивается к успешному минту: успех требует прежней проверки finalized-транзакции и соответствующего Core NFT. Неопределённый исход блокирует новый минт до проверки блокчейна.

Диагностика разделяет walletAttempt.method/outcome и submission.state. URL RPC, ключ, подписанные байты и произвольные сообщения провайдера в экспорт не включаются. URL остаётся в памяти до перезагрузки; ключ не добавлен в GitHub или статический сайт. Публичный Solana RPC и его варианты адреса не допускаются в новый режим отправки.

## Проверки и ограничения

- Модули: реальные SDK-транзакции с тестовыми ключами, криптографическая проверка, подмена сообщения/подписей, каноничность пакета; единственный POST и совпадение подписи ответа; HTTP 429, таймаут/abort, неизвестный исход, поздние ответы; сохранение журнала до отправки и гонки с восстановлением.
- Браузерная матрица расширена до 51 сценария Devnet плюс 12 основного сайта для каждого из Chromium, Firefox и WebKit. Добавлены выбор отдельного пути при наличии Wallet Standard, отсутствие возможностей, отказ/внутренняя ошибка, неподписанные/изменённые байты, сброс RPC, reload и имитация возврата из BFCache.
- RPC и кошельки в автоматических браузерных проверках имитируются. Криптографически успешный сценарий использует отдельные созданные тестовые ключи и имитацию RPC, без ключа владельца и без отправки в блокчейн.
- Реальный новый путь на Android Phantom, реальный Core NFT владельца и Mainnet этим обновлением ещё не подтверждены. Продажи остаются закрытыми. Возможность стороннего RPC или кошелька вернуть ошибку сохраняется; проверяется корректная обработка таких исходов.
