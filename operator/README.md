## Воспроизведение

Из корня репозитория:

Использовать указанную версию npm: npm 10 иначе обрабатывает optional peer-зависимость `utf-8-validate` и не воспроизводит этот lockfile. Чистая установка npm 11.9.0 проверена; CI закрепляет ту же версию.

```sh
npm ci --prefix operator --ignore-scripts --no-audit --no-fund
npm run --prefix operator setup
npm run --prefix operator verify
mkdir -p private
node operator/prepare.mjs private/NEW
node operator/verify-preparation.mjs private/NEW
```

`NEW` заменить именем новой папки. Повторный запуск подготовки в ту же папку завершается до перезаписи. Эти две команды работают офлайн: подготовка записывает пакет, проверка только читает его и сверяет с политикой. Аудит предназначен для свежего пакета, который ещё не отправлялся в сеть; это не проверка изменённого CLI cache после развёртывания. По умолчанию адрес коллекции пуст; необязательный `COOLBEARS_COLLECTION` задаёт публичный адрес, для которого офлайн проверяется только формат, не существование и не полномочия. Продажи закрыты, `readyToDeploy=false`. `release-plan.json` описывает план, а не подтверждает создание коллекции, резервного NFT или машины. Состав пакета и последующие этапы: [PRODUCTION_READINESS.md](PRODUCTION_READINESS.md).

RPC задаётся явно через `COOLBEARS_RPC_URL`. При отсутствии настройки автоматического переключения на публичный RPC нет. Для сервера за системным HTTPS proxy в Node 24 использовался `NODE_USE_ENV_PROXY=1`.

```sh
npm run --prefix operator check:rpc
npm run --prefix operator simulate
npm run --prefix operator mplx -- cm create --help
```

Проверка RPC выполняет только четыре чтения. Симуляция отправляет `simulateTransaction` с отключённой проверкой отсутствующей подписи владельца, никогда `sendTransaction`; она не доказывает, что кошелёк подпишет транзакцию. Одно успешное чтение или симуляция публичного RPC не гарантирует стабильную работу на телефоне.

## Совместимость CLI с сервером

CLI 0.4.3 импортирует поддержку Ledger USB при старте даже для чтения баланса с файловым ключом. В этой среде это вызывает ошибку libusb/udev. `setup` применяет проверяемое по SHA-256 изменение: импорт `LedgerSigner.js` переносится внутрь уже существующей ветки `usb://ledger`. Сами signer, формирование, отправка и подтверждение транзакций не заменяются. Ветка Ledger сохраняется. Скрипт идемпотентен и отказывается изменять неизвестную версию исходника. Нативные USB-функции здесь не тестировались.

## Историческая отдельная проверка CLI в Devnet

`run-cli.mjs` запускает команды официального CLI. В данной серверной среде нужен явный preload транспорта до загрузки SDK:

```sh
node --import ./operator/cli-transport.mjs operator/run-cli.mjs toolbox sol balance FNytKprG3JukM81svBhCrgHAEHht3oUgpXZFUkUbCW6y --rpc "$COOLBEARS_RPC_URL" --keypair /absolute/path/to/devnet-test-key.json --json
node --import ./operator/cli-transport.mjs operator/cost.mjs
```

Транспорт использует системный HTTPS proxy через curl, один запрос без скрытых повторов, с ограничением времени. Это серверная настройка, не исправление сети телефона. По умолчанию отправка запрещена. Режим с `COOLBEARS_LAB_OPERATION` разрешает одну транзакцию только от ранее сохранённого отдельного тестового кошелька Bjst…qyF в проверенной Devnet. Требуется новая абсолютная папка операции: существующая папка блокирует повторный запуск. Перед единственной отправкой проводится симуляция с проверкой подписей, signed bytes и signature сохраняются с fsync в приватный журнал. При неизвестном результате повтор команды запрещён; сначала проверять ту же подпись.

Подтверждение идёт через getSignatureStatuses по HTTPS; WebSocket через эту среду не требуется. Результат дополнительно проверяется до finalized с err=null, независимо от текста успеха CLI. В CLI 0.4.3 обнаружена ветка confirmTransaction.js, допускающая успех при положительном context.slot без проверки value.err; собственная проверка не допускает этого. Само формирование и подписание инструкций CLI не заменено.
