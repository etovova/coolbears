# Новый процесс выпуска CoolBears

**Текущий результат:** лабораторная проверка машины на две позиции завершена. Владелец прислал отчёт v6 реального Phantom Android: `stage=verified`, NFT `8c2rbr5eG2v7FhEJ2PJ78UemoQRfbiwJ9jJoikiWiWER`, подпись `519EGskF9cwHQCtmFuMxXfPCnquxY83pU3ajUzhbXGUQoNTvhbQY85YwLg4KVS6487K4smor8KGKwPkexTQzGA7b`. Он также подтвердил медведя и анимацию. Это отчёт владельца и проверка сайта, а не независимое повторное чтение цепочки ассистентом. Повторный минт не требуется; [подробности и ограничения](../devnet/README.md). Физические Solflare/Backpack ещё не проверены.

Путь Phantom `signTransaction` → собственный Helius RPC проверен в v6. Для v7 подготовлен [общий Devnet RPC](../rpc-proxy/README.md), но `settings.siteRpc` пока пустой и сервис не развёрнут. Исторические отчёты ниже про один выпущенный NFT и addressGate на лабораторный Bjst описывают прежний этап, а не текущее состояние.

Используется Metaplex CLI 0.4.3, Node 24.19.0 и npm 11.9.0. Создание коллекции и машины выполняется отдельно от сайта. Сайт сохраняет оформление и закрытые продажи. Код прежней панели и тестовой страницы не используется.

## Что готово

- Воспроизводимая установка CLI и SDK с точными версиями и lockfile.
- Подготовка и публикация 10000 скрытых JSON без изменения изображений и без финальных атрибутов. Все файлы проверены в сборке и Git; восемь граничных URL проверены побайтно на домене.
- Конфигурация Core Candy Machine, cache для CLI и плагин роялти. Конфигурация закрыта addressGate; цена соответствует утверждённой политике.
- Проверка доступности Devnet, программ, баланса и blockhash без записи в сеть.
- Симуляция создания коллекции/NFT и небольшой машины в реальной Devnet. Это не выпуск NFT и не проверка подписи Phantom.
- Историческое создание тестовой коллекции, машины на 2 позиции, загрузка обеих записей и первый платный mint лабораторным подписантом на кошелёк владельца. Все четыре операции finalized; это отдельная лабораторная коллекция. Позднее владелец завершил второй mint через Phantom + Helius, как указано выше.

## Воспроизведение

Из корня репозитория:

Использовать указанную версию npm: npm 10 иначе обрабатывает optional peer-зависимость `utf-8-validate` и не воспроизводит этот lockfile. Чистая установка npm 11.9.0 проверена; CI закрепляет ту же версию.

```sh
npm ci --prefix operator --ignore-scripts --no-audit --no-fund
npm run --prefix operator setup
npm run --prefix operator verify
mkdir -p private
node operator/prepare.mjs private/new-cli-project
```

Выходная папка должна быть новой. Повторный запуск в ту же папку завершается до перезаписи. Адрес коллекции пока пуст: CLI откажется создавать машину до появления настоящей коллекции. Подготовленные файлы не считаются опубликованными или загруженными on-chain.

RPC задаётся явно через `COOLBEARS_RPC_URL`. При отсутствии настройки автоматического переключения на публичный RPC нет. Для сервера за системным HTTPS proxy в Node 24 использовался `NODE_USE_ENV_PROXY=1`.

```sh
npm run --prefix operator check:rpc
npm run --prefix operator simulate
npm run --prefix operator mplx -- cm create --help
```

Проверка RPC выполняет только четыре чтения. Симуляция отправляет `simulateTransaction` с отключённой проверкой отсутствующей подписи владельца, никогда `sendTransaction`; она не доказывает, что кошелёк подпишет транзакцию. Одно успешное чтение или симуляция публичного RPC не гарантирует стабильную работу на телефоне.

## Следующий этап

1. Выбрать и настроить личный Devnet RPC и кошелёк оператора. Ключи хранятся на доверенном компьютере; приватные ключи владельца не запрашивать в чате.
2. Профинансировать полную машину только после выбора окончательной конфигурации. Для нынешних 9999 config lines SDK рассчитывает 871827 байт; реальный Devnet RPC 21 сентября вернул 4429531400 lamports (4.4295314 тестового SOL) только за аккаунт машины. Это не полный бюджет: collection, guard, asset и комиссии учитываются отдельно. На указанном кошельке владельца во время расчёта было 0.2956272 Devnet SOL.
3. Проверить свежую конфигурацию и соответствие уже опубликованным скрытым метаданным перед записью config lines.
4. Создать коллекцию официальной командой `mplx core collection create` с подготовленным `collection-plugins.json`. Идентичность подписанта и update authority должны быть проверены до отправки.
5. Создать Core Candy Machine через `mplx cm create`, затем `mplx cm insert` и `mplx cm fetch`. После неопределённого результата команды не запускать создание заново: сначала восстановить адрес/подпись и проверить состояние.
6. Перенести проверенный Devnet-процесс в будущий основной интерфейс при закрытых продажах; отдельно проверить физические Solflare/Backpack и другие устройства. Успешный Phantom Android уже описан выше. Не повторять завершённый лабораторный минт и не возвращать старую панель.

Полный выпуск коллекции, производственный интерфейс продаж, пакетные покупки и раскрытие ещё не завершены. Продажи не открывать автоматически. Прежние тесты и старые адреса не подтверждают новый процесс; новая отдельная Devnet-проверка описана ниже.

## Совместимость CLI с сервером

CLI 0.4.3 импортирует поддержку Ledger USB при старте даже для чтения баланса с файловым ключом. В этой среде это вызывает ошибку libusb/udev. `setup` применяет проверяемое по SHA-256 изменение: импорт `LedgerSigner.js` переносится внутрь уже существующей ветки `usb://ledger`. Сами signer, формирование, отправка и подтверждение транзакций не заменяются. Ветка Ledger сохраняется. Скрипт идемпотентен и отказывается изменять неизвестную версию исходника. Нативные USB-функции здесь не тестировались.

## Историческая отдельная проверка CLI в Devnet

`run-cli.mjs` запускает команды официального CLI. В данной серверной среде нужен явный preload транспорта до загрузки SDK:

```sh
node --import ./operator/cli-transport.mjs operator/run-cli.mjs toolbox sol balance FNytKprG3JukM81svBhCrgHAEHht3oUgpXZFUkUbCW6y --rpc "$COOLBEARS_RPC_URL" --keypair /absolute/path/to/devnet-test-key.json --json
node --import ./operator/cli-transport.mjs operator/cost.mjs
```

Транспорт использует системный HTTPS proxy через curl, один запрос без скрытых повторов, с ограничением времени. Это серверная настройка, не исправление сети телефона. По умолчанию отправка запрещена. Режим с `COOLBEARS_LAB_OPERATION` разрешает одну транзакцию только от ранее сохранённого отдельного тестового кошелька Bjst…qyF в проверенной Devnet. Требуется новая абсолютная папка операции: существующая папка блокирует повторный запуск. Перед единственной отправкой проводится симуляция с проверкой подписей, signed bytes и signature сохраняются с fsync в приватный журнал. При неизвестном результате повтор команды запрещён; сначала проверять ту же подпись.

Подтверждение идёт через getSignatureStatuses по HTTPS; WebSocket через эту среду не требуется. Результат дополнительно проверяется до finalized с err=null, независимо от текста успеха CLI. В CLI 0.4.3 обнаружена ветка confirmTransaction.js, допускающая успех при положительном context.slot без проверки value.err; собственная проверка не допускает этого. Само формирование и подписание инструкций CLI не заменено.

```sh

```

Для текущего результата владельца использовать чтение сохранённой операции через страницу `/devnet/` либо `readState`/`inspectOperation` из `devnet/core.mjs`. Она проверяет сохранённую подпись, срок blockhash, Core asset, коллекцию, guard, счётчик и оплату; новых транзакций не создаёт и не отправляет.
