# Новый процесс выпуска CoolBears

Используется Metaplex CLI 0.4.3, Node 24.19.0 и npm 11.9.0. Создание коллекции и машины выполняется отдельно от сайта. Сайт сохраняет оформление и закрытые продажи. Код прежней панели и тестовой страницы не используется.

## Что готово

- Воспроизводимая установка CLI и SDK с точными версиями и lockfile.
- Подготовка 10000 скрытых JSON без изменения изображений и без финальных атрибутов.
- Конфигурация Core Candy Machine, cache для CLI и плагин роялти. Конфигурация закрыта addressGate; цена соответствует утверждённой политике.
- Проверка доступности Devnet, программ, баланса и blockhash без записи в сеть.
- Симуляция создания коллекции/NFT и небольшой машины в реальной Devnet. Это не выпуск NFT и не проверка подписи Phantom.

## Воспроизведение

Из корня репозитория:

Использовать указанную версию npm: npm 10 иначе обрабатывает optional peer-зависимость `utf-8-validate` и не воспроизводит этот lockfile. Чистая установка npm 11.9.0 проверена; CI закрепляет ту же версию.

```sh
npm ci --prefix operator --ignore-scripts --no-audit --no-fund
npm run --prefix operator setup
npm run --prefix operator verify
mkdir -p private
node operator/prepare.mjs private/new-cli-project
```

Выходная папка должна быть новой. Повторный запуск в ту же папку завершается до перезаписи. Адрес коллекции пока пуст: CLI откажется создавать машину до появления настоящей коллекции. Подготовленные файлы не считаются опубликованными или загруженными on-chain.

RPC задаётся явно через `COOLBEARS_RPC_URL`. При отсутствии настройки автоматического переключения на публичный RPC нет. Для сервера за системным HTTPS proxy в Node 24 использовался `NODE_USE_ENV_PROXY=1`.

```sh
npm run --prefix operator check:rpc
npm run --prefix operator simulate
npm run --prefix operator mplx -- cm create --help
```

Проверка RPC выполняет только четыре чтения. Симуляция отправляет `simulateTransaction` с отключённой проверкой отсутствующей подписи владельца, никогда `sendTransaction`; она не доказывает, что кошелёк подпишет транзакцию. Одно успешное чтение или симуляция публичного RPC не гарантирует стабильную работу на телефоне.

## Следующий этап

1. Выбрать и настроить личный Devnet RPC и кошелёк оператора. Ключи хранятся на доверенном компьютере; приватные ключи владельца не запрашивать в чате.
2. Проверить точную стоимость и финансирование полной машины. Схема config lines сохраняет четырёхзначные имена; она требует загрузки записей и большего rent, чем hidden settings. Расчёт полной стоимости ещё не выполнен.
3. Опубликовать только скрытые метаданные и побайтно проверить все ссылки. Генератор пока пишет локальные файлы.
4. Создать коллекцию официальной командой `mplx core collection create` с подготовленным `collection-plugins.json`. Идентичность подписанта и update authority должны быть проверены до отправки.
5. Создать Core Candy Machine через `mplx cm create`, затем `mplx cm insert` и `mplx cm fetch`. После неопределённого результата команды не запускать создание заново: сначала восстановить адрес/подпись и проверить состояние.
6. После настоящего теста создания, загрузки и минта подключить отдельный mint UI по официальной документации Metaplex и протестировать физические Phantom и Solflare. Не возвращать старую панель.

Реальные операции выпуска, полноценный mint UI, пакетные покупки и раскрытие в этой точке ещё не реализованы и не проверены. Продажи не открывать автоматически. Прежние тесты и старые адреса не подтверждают новый процесс.

## Совместимость CLI с сервером

CLI 0.4.3 импортирует поддержку Ledger USB при старте даже для чтения баланса с файловым ключом. В этой среде это вызывает ошибку libusb/udev. `setup` применяет проверяемое по SHA-256 изменение: импорт `LedgerSigner.js` переносится внутрь уже существующей ветки `usb://ledger`. Сами signer, формирование, отправка и подтверждение транзакций не заменяются. Ветка Ledger сохраняется. Скрипт идемпотентен и отказывается изменять неизвестную версию исходника. Нативные USB-функции здесь не тестировались.
