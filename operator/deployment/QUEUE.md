# Возобновляемая очередь владельца

Очередь читает существующий полный Devnet bundle и показывает следующий ручной
шаг. Состояние восстанавливается из журнала после перезапуска. Новых ключей,
паролей, коллекций или сетевых запросов команда `status` не создаёт. Она не
расшифровывает vault и не проверяет свежесть blockchain-состояния.

Из корня репозитория:

```sh
node operator/deployment/owner-console/cli.mjs status private/DEPLOYMENT
node operator/deployment/owner-console/cli.mjs prepare-next private/DEPLOYMENT
```

`status` проверяет canonical manifest, зашифрованный envelope, права и историю
существующего bundle. Вывод содержит привязку к revision/head, счётчик завершённых
операций и массив аргументов следующей команды. `<bundle>` в подсказке нужно
заменить локальным путём; это не готовая строка shell. Секреты, путь к bundle,
RPC URL, транзакционные bytes и поля vault в отчёт не входят. Сам отчёт —
приватный операторский материал, его не нужно публиковать на сайте.

| Сохранённое состояние | Следующее действие |
| --- | --- |
| Ещё нет попытки | `prepare-next` либо `prepare <bundle> <step>` |
| Запрос подготовлен, кошелёк его ещё не получил | `serve <bundle>`, затем явная подпись |
| Кошелёк получил запрос, полного ответа нет | Восстановить ответ в прежнем браузере/локальной панели или импортировать сохранённый JSON |
| Подпись сохранена | Отдельный `send-one <bundle> <step> --devnet-send` |
| Отправка занята, принята или исход неизвестен | `resume <bundle> <step>`; новая отправка запрещена |
| Неуспех/истечение доказаны либо неподписанная попытка отменена | Только отдельный `prepare-retry <bundle> <step>` |
| Все шаги verified | Очередь завершена; продажи остаются закрытыми |

Команды `send-one`/`resume` принадлежат `operator/deployment/send-cli.mjs`.
Остальные команды принадлежат `owner-console/cli.mjs`. Проверка failure/expiry
не выбирается автоматически по таймауту или пустому receipt: нужны явные
review-команды из [RETRY.md](RETRY.md) и [EXPIRY.md](EXPIRY.md).
Подсказка `serve` при потерянном ответе **не разрешает новую подпись**. Без полного
сохранённого ответа попытка остаётся заблокированной.

`prepare-next` выбирает ровно один ещё не начатый шаг. До пароля фиксируются
manifest, revision и head. После ввода пароля эта привязка сверяется заново до
расшифровки vault/RPC. Конкурирующая подготовка или закрытие попытки останавливает
команду; новая попытка того же шага не наследует старый выбор. Далее действуют
прежние fresh preflight, unsigned simulation и атомарная запись `prepare`.
Повтор команды при готовом запросе не открывает кошелёк, не просит пароль и не
создаёт вторую попытку. Retry никогда не выбирается командой `prepare-next`.

Панель владельца показывает количество `verified` из общего числа операций.
Подписанные и принятые RPC попытки не увеличивают завершённый прогресс. После
обновления страницы сохранённая попытка отображает своё фактическое журнальное
состояние. Панель остаётся привязана к одному запросу; для следующей операции
нужны отдельная подготовка и запуск панели. Автоматической подписи очереди,
`signAllTransactions`, фонового отправителя и автоматического retry нет.

Это последовательная очередь с подсказками, не готовая пакетная загрузка всей
коллекции. Реальные custody/пароль/endpoint, свежий бюджет, удобная групповая
подпись, buyer flow и физические кошельки/телефоны ещё требуют завершения.
Встроенные тестовые кошельки и макеты телефона не подтверждают работу настоящих
Phantom/Solflare. Старую лабораторию 2/2 не повторять, историю не очищать.
