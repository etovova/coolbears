## RPC сайта и другие кошельки

Путь v6 с явным выбором «Phantom: отправлять через свой RPC» проверен владельцем на одном телефоне. Предыдущие HTTP 429 и ошибки Wallet Standard относятся к более ранним попыткам; они не являются текущим результатом этого NFT и не считаются исправленными только благодаря успеху другого маршрута.

22 сентября 2026 общий сервис развёрнут в Cloudflare. Независимая проверка только чтением подтвердила CORS, Devnet genesis и текущие аккаунты машины/guard/коллекции с тиражом 2/2. В `settings.siteRpc` настроен публичный адрес `https://coolbears-devnet-rpc.yauheni84.workers.dev/rpc` без API-ключа; клиент v7 пересобран. **Физический тест интерфейса v7 не проводился; состояние публикации этой сборки подтверждается workflow GitHub Pages.** После публикации обычная кнопка Phantom выберет отдельную подпись и отправку через RPC сайта. При ошибке автоматического переключения на отправку кошельком нет. Устройство и ограничения: [rpc-proxy/README.md](../rpc-proxy/README.md). Ручной адрес в дополнительных настройках по-прежнему действует только до перезагрузки; API-ключ не переносится в репозиторий или журнал.

Solflare, Backpack и совместимые Wallet Standard кошельки предусмотрены в интерфейсе. Их физические подписи, другие телефоны, настольные расширения и аппаратные устройства этим успешным Phantom-тестом не подтверждаются.

Цена guard — 0,5 Devnet SOL; получателем является тот же кошелёк владельца. Дополнительно оплачиваются тестовые комиссии и хранение аккаунта NFT. Владелец не передаёт приложению свой приватный ключ.

## Устройство и проверенный объём

- Официальные Core SDK закреплены в `package-lock.json`. Сборка включает Buffer для зависимостей web3.js.
- Обычный Wallet Standard использует явную сеть `solana:devnet`; стандартный injected-путь Phantom/Solflare применяет `signAndSendTransaction`. Отдельный путь Phantom применяет только `signTransaction`; сеть кошелька выбирает пользователь. Blockhash и все проверки приложения относятся только к Devnet.
- В обычном пути кошелёк подписывает и отправляет частично подписанный v0 mint. В пути Phantom + свой RPC приложение проверяет неизменность сообщения и обе подписи, сохраняет координаты и выполняет один RPC `sendTransaction` без автоматического повтора HTTP-запроса. Неизвестный результат проверяется по той же операции. Ключ нового asset существует только в памяти подготовки; ключ плательщика никогда не запрашивается приложением.
- Публичный журнал записывается перед подписью. Web Locks не дают двум вкладкам начать отправку одновременно. Неопределённый результат запрещает новую попытку.
- Подтверждение — HTTPS polling до `finalized`, проверка `err`, программы Core, фактического владельца, коллекции, имени и URI. Положительного slot недостаточно.
- Истечение признаётся только после finalized blockhash expiry и повторной проверки отсутствия asset/подписи с контекстом не старее проверки expiry. После тайм-аута подпись не запрашивается повторно автоматически.
- Отказ кошелька с кодом 4001 позволяет новую попытку. Повторяются только чтения/симуляции при временных сетевых ошибках: не более трёх попыток, с паузой и соблюдением Retry-After. Ошибки доступа и некорректные ответы не повторяются. Окно ответа кошелька ограничено 60 секундами; поздняя подпись сохраняется и не затирается старым результатом проверки.
- Лимит одной попытки RPC — 25 секунд; общий срок запроса с очередью/повторами — 45 секунд; сетевой этап страницы — до 90 секунд. Очередь и число попыток ограничены. После истечения срока подпись не повторяется.
- В подготовленной сборке v7 адресом по умолчанию служит настроенный RPC сайта, а кнопка сброса возвращает к нему. Необязательный свой HTTPS RPC задаётся в закрываемом разделе страницы: введённый адрес/ключ сохраняется только в памяти до перезагрузки, не записывается в localStorage, журнал, диагностику или ссылки открытия кошелька. Сеть проверяется по genesis hash до чтения аккаунтов. При неверной сети минт заблокирован. Общий публичный RPC выбирается только при пустой настройке `siteRpc`; автоматического переключения на него при отказе RPC сайта нет. Успешный физический минт v6 использовал прямой Helius владельца, а не новый общий сервис.
- Заблокированное/повреждённое localStorage запрещает минт до сохранения операции; экспорт диагностики доступен даже при запрете доступа к storage. Публичный журнал неопределённой операции не очищается автоматически.
- `npm run test:devnet` включает протоколы RPC/Wallet Standard, частичную подпись, журнал и recovery. `tests/devnet.browser.mjs` и `tests/devnet-matrix.browser.mjs` проверяют браузерную связку с имитацией RPC/кошелька. `tests/main.browser.mjs` — основной сайт, языки, калькулятор и подключение. Отчёты сохраняют фактический объём и ограничения; эмуляция viewport/UA/touch не является проверкой реального телефона.


Исторический отчёт до завершения лабораторного минта `operator/reports/wallet-test-preflight.json`: точный браузерный builder успешно симулирован; другой minter отклонён `AddressNotAuthorized` 6033. Проверка подписей в этой симуляции выключена, поскольку подпись владельца доступна только в его кошельке. Новых NFT во время этой исторической симуляции не создавали. Отчёт не описывает текущий остаток тиража; после завершения теста не запускать его как инструкцию нового минта.
