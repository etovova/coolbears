## Важные результаты API

Чтение Certificate Packs / Rulesets недоступно текущему подключению. HTTPS
проверен реальными запросами; www выполнен поддерживаемым assets-only способом.
Две попытки прикрепить apex до удаления старых A вернули 100117 — конфликт
externally managed DNS. Даже override из текущего Wrangler не заменил их.
После сохранения полного снимка четыре A удалены, затем Custom Domain создан
успешно; на случай неуспеха была подготовлена немедленная обратная запись.
Для www так же сохранён/удалён только его прежний CNAME и создан Custom Domain.
Не повторять ошибочные попытки override и не трогать почтовые записи.

## Продолжение и откат

Сначала проверить распространение DNS обычным HTTPS-путём. Не пересоздавать
Workers, не повторять NS/OAuth/загрузку основного пакета и не очищать браузер.
Не считать 429 устранённым переносом сайта; это отдельный этап RPC. Не расширять
CORS на www/staging, не повторять mint и не запускать mainnet.

GitHub Pages сохранён для возврата. При необходимости отката удалить только
новые Custom Domain привязки статического сайта и www; проверить оставшиеся
автоматические записи DNS и убрать только относящиеся к этим привязкам записи.
Восстановить четыре DNS-only apex A 185.199.108.153, 185.199.109.153,
185.199.110.153, 185.199.111.153 и DNS-only www CNAME etovova.github.io с
исходным Auto TTL. Полные исходные records и IDs находятся в приватном файле
продолжения владельца. Вернуть always_use_https=off, если откат должен вернуть
все прежние настройки. Само делегирование Cloudflare для отката хостинга менять
не требуется. Сертификаты Custom Domains не удаляются автоматически при
отвязке; не удалять другие сертификаты/Workers и не затрагивать RPC.

CI проверяет код без публикации. Запись Git commit не обновляет Cloudflare сама.
Новые публикации должны использовать проверенный пакет и отдельный deployment.
